Constraint satisfaction problems

  • Dv1 denotes the domain of v1
  • D denotes the assignment space. This is the cross product of all Dvn in V

A CSP is a set of variables (each with there own domain) and some hard constraints which specify the legal assignment of variables. We try to find a solution (assignment which doesn't violate constraints), sometimes for optimization problems we also try to minimise the cost given by the cost function for each assignment of a value to variable. We may not always be able to find an assignment so we try and find the one with the least constraint violations. If variables are in the infinite domain then we cannot enumerate them so we will want a constraint language (ordering of things). Infinite domains are solvable with linear constraints but undecidable with non-linear ones.

Constraint types

  • Unary: on a single variable. e.g. X > 0
  • Binary: pair of variables. x =\= y
  • Higher-Order constraints: 3+ variables
  • Preferences/ soft constrains: cost functions. "We prefer lower values of x"

Generate-and-test algorithm

Basically your standard brute force. Just enumerate all the possible combinations till you find (or not) one which satisfies all the constraints. This is O(|D|) -- so pretty fucking slow.

Backtracking algorithms

We can terminate a branch if we find the partial assignment breaks constraints. So we can do DFS and evaluate constraints as soon as we have appropriate variables, if it breaks then unassign last var and try new assignment. Repeat till exhausted variable and then backtrack up another variable. The solution will occur at depth n, the assignment order doesn't matter (as is commutative).

Heuristics

  • Minimum remaining values: Assign variable with fewest legal moves.This var has fewest legal moves and so is most likely to break it. If we break it quickly we can cut of the entire branch massively reducing the search space.
  • Degree heuristic: Choose var with most constraints on remaining variables. This reduces the branching factor further down the tree
  • Least constraining value: given a variable, choose the least constraining value (removes the fewest legal values of remaining vars)

CSP as graph search

Each node is a partial assignment. Start with empty node. Pick a non assigned variable, for each value that is legal add a new node with the value appended to the parent node and a edge to the parent node. Repeat till reach node with full legal assignment.

Constraint network

  • (circle) Node for each variable
  • Domain of values for each variable node
  • (Rectangle) Node for each constraint
  • arc from variable X node to constraint node C is C involves X

Consistency

We want to reduce the search space by removing values which will always fail. If C only concerns X (C has scope X) then arc 〈X,C〉is domain consistent if every value of X satisfies C. In general is C has scope {X,Y,...} then arc 〈X,C〉is arc consistent if for every value of X there is an assignment (using current domains) such that C is satisfied. If all arcs consistent then network is arc consistent. We should remove any values which make a arc non consistent so that the network is arc consistent (and quicker to process). If we update the domain of one node to make an arc consistent then we also need to recheck all the C's which have X in their scope. Once a network is arc consistent we have several cases:

  • One domain is empty: cannot satisfy
  • Each domain has size 1: We have found unique solution
  • Some domains have more than one solution: there may (or may not) be a solution -- so we need to search
Alternatively, instead (or in addition to search) we can domain split. We split a domain then make each separate network arc consistent, there is a decent change this leads to a solution. Domain splitting relates to the problem structure, say each subproblem c has n variables. Then a problem has n/c subproblem's which take at most d^c time to solve, then worst case n/c * d^c is linear.
