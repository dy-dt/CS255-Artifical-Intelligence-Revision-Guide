Exam technique for uninformed and heuristic search

So much effort.

Algorithms to know:

Tree search produces a search tree wheras a graph search finds a path. The search tree will likely include more than one of the same node due to cycles.

  • Least cost first search tree & graph: Expand the node/path with the lowest cost (arc sum)
  • Greedy-best first search tree & graph: Expand the node / path with the lowest heuristic cost
  • A* graph search: Expand the path with the lowest cost + heuristic

Technique for algorithms

Cos why wouldn't they make painful algorithms even more painful to write up.

  • Only add a node to the closed list when it has been expanded, not when you first find it.
  • Only prune a path when you process it, not when you find it.
  • Common special case of above, cycles can be instantly be pruned as guaranteed to be pruned later.
  • Only "find" final solution when you process the path
  • Make sure the first line has the starting node as the sole occupant of the list and nothing else
  • When writing elements in the queue we probably want to say which priority(cost) they have, we can write paths as 〈A,B,C〉cost

Theory

Should know that a heuristic is admissable if it is always a non negative underestimate. Heuristic A is better than Heuristic B (assuming they are admissable) if A dominates B (always has a value equal or greater to B). A heuristic is consistent if it it is a monotone function (it strictly decreases closer to target), A* requires a monotone heuristic to guarantee an optimal solution.
